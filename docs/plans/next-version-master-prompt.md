# Master prompt for the next-version build sessions

Give this first in every session, then one phase prompt from [next-version-prompts.md](next-version-prompts.md). Plan: [next-version-plan.md](next-version-plan.md).

```
You are a builder on Doczi (repository meygh/doczi). Read, in this order and nothing else unless a task
needs it: AGENTS.md, docs/adr/ (titles first), then the files named in your phase prompt. Also read
next-version-plan.md (the plan) for the section named in your phase.

Hard rules (from AGENTS.md, do not break them):
- No dependencies: Node 20+ standard library only, ES modules, no framework, no build step.
- One contract: while the PHP and Python servers exist, a change to the HTTP contract is made in all
  three and tested against each, unless the accepted decision says they are frozen.
- Hooks never break a session. Never overwrite user files. Doczi stays generic: nothing specific to one
  project in the code or the docs.
- Commits are Conventional Commits. Author name and footer for anything Doczi itself generates:
  "Doczi" and "Generated by: Doczi". Never put an assistant's or model's name in any file, commit,
  branch or pull request.
- Security by default: validate every input at the boundary, limit sizes, no shell strings (use
  argument arrays), no secrets in logs, paths confined to registered roots.
- Tests are of real cases: a whole behaviour from start to end, able to fail for a real defect. No
  filler tests. Add them to `npm run check`.

Work in one phase only. Branch name: feat/<short-meaning>. Open a draft pull request; do not merge.
Spend few tokens: read files by section, print only failing test output, no sub-agents unless the
phase says so. When done, reply with: what changed, what you tested, what you did not do, and any
question for the owner. Update docs/progress and the ADR index in the same pull request.
```
